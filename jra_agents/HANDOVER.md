# 引き継ぎメモ: 「人」に注目したモデル改善の方針

スマホからの避難作業中（2026年11月）にまとめた方針メモ。
PCの競馬アプリ側で Claude Code に読ませて、そのまま作業の出発点にできる。

## 背景

- レース全体の特徴を検討する方向では、モデルの改善が小さくなってきた。
- 次は調教師・騎手・馬主・エージェントなど、一人一人に注目した特徴を試したい。
- このフォルダには、その材料としてエージェント一覧と、1週末分（2026年11月7・8日、全72レース）の試し集計が入っている。

## 最初にやること: 今の予想モデルと買い目のレビュー

新しい特徴を試す前に、今の予想モデルと買い目のコードを全部読んでもらい、問題点と改善案を出してもらう。
新しい検討は効くかどうか試すまで分からないが、既存のコードの見直しは、問題が見つかればそのまま改善になるため。
このメモの「進め方」以降は、レビューのあとに、今のモデルに合わせて取捨選択する。

### 見てもらう観点

1. **データ漏れ**: レース後にしか分からない情報（確定オッズ、当日の馬体重の扱い、レース後に更新される成績など）を、予測の時点で使っていないか。
2. **検証の分け方**: 時期で分けて検証しているか。同じレースや同じ期間のデータが学習と検証の両方に入っていないか。
3. **回収率の計算**: 払戻金の扱い（同着、返還、取消）、買い目の点数と金額の数え方が正しいか。
4. **買い目のロジック**（予想の精度とは別に見る）: 点数、金額配分、見送りの基準。精度が同じでも、買い方だけで回収率が変わる。
5. **過学習**: 特徴の数や調整の回数に対して、検証期間が短すぎないか。
6. **改善の優先順位**: 見つかった問題と、このメモの案（「人」に注目した特徴、馬体重）のうち、どれから手をつけるべきか。

### 頼むときのコツ

- **最初は直させない**: まず「読んで、問題点と改善案を重要な順に出して」と頼む。一覧を見て、直すものを選んでから修正に進む。意図しない書き換えを防ぐため。
- **直す前の数字を記録する**: 修正前の回収率・的中率などを同じ条件で記録しておき、修正のたびに比べる。
- **一度に一つずつ直す**: 複数をまとめて直すと、どの修正が効いたのか分からなくなる。
- **モデルが実際より良く見えていた、という結果もありうる**: データ漏れや計算の誤りが見つかると、成績が下がることがある。それは改善の一部として受け止める。

## 基本方針

「人ごとの成績を足す」より、**その人のいつもの行動からのずれを特徴にする**。
騎手や厩舎の実力そのものは、すでに人気（オッズ）にかなり織り込まれているため。

## 進め方

### 1. まず、今のモデルが外している相手を調べる

- 予測と結果の差を、調教師・騎手・馬主・エージェントごとに集計する。
- 特定の人で一貫して過小評価または過大評価していれば、そこに伸びしろがある。
- 偏りが出なければ、人に寄せても改善は薄い可能性が高い。
- 新しい特徴を作る前にできるので、最初にやる。

### 2. 「いつもとの違い」を特徴にする

| 特徴 | 内容 |
|---|---|
| 乗り替わり | 前走より上位の騎手に替えたか、下げたか |
| 厩舎内の序列 | その厩舎がよく使う騎手のうち、今回は何番手の騎手か |
| 同エージェントの同時出走 | 同じレースに同じエージェントの騎手が複数いるとき、どちらが人気馬に乗っているか |
| 馬主と騎手の付き合い | その馬主がその騎手を使う頻度 |

### 3. 少ない回数を信じすぎない

- 人ごとに分けると1人あたりの件数が少なく、たまたまの数字を学習しやすい。
- 件数の少ない人は全体平均に寄せる。極端に少ない人は「その他」にまとめる。
- 集計には、そのレースより前のデータだけを使う（結果を先に見てしまわないように）。

### 4. 人気に勝てているかで評価する

- 的中率ではなく、「人気だけの予測」に上乗せできたか、回収率が上がったかを見る。
- 検証は時期で分ける（古い期間で作り、新しい期間で確かめる）。

### 5. エージェントのデータは今から貯める

- JRAのPDFには「現在の担当」しか載っていない。過去のレースに今の担当を当てはめると、当時と違っている場合がある。
- PDFを毎週保存して、日付つきで残していく。`build.py` でそのままデータにできる（手順は `RECOVERY.md`）。

## 着手の順番

1. 乗り替わり
2. 調教師×騎手
3. エージェント
4. 馬主

前の2つは過去データだけで作れて、効果も出やすいとされているため。

## 追加の方針: 馬体重の増減は「ベスト体重との差」で見る

馬体重の急増・急減は普通は嫌われるが、細かった馬に体重がついた、太かった馬が絞れた、のようにベスト体重への変化もある。
調教の失敗（太め残り・消耗）と成功（成長・仕上がり）を見分けるための特徴案。

### 1. ベスト体重に近づいたか、離れたか

- その馬が好走したとき（例: 3着以内）の体重の平均を「ベスト体重」とする。そのレースより前の結果だけで計算する。
- 今回の体重がベスト体重に近づいた増減なら良い変化、離れた増減なら悪い変化の候補。
- 例: ベスト480kgの馬が、前走466kgから今回478kgなら「+12kgだが戻った」。前走480kgから492kgなら「+12kgで太め」。
- 好走歴がない馬は、勝ち上がり前の平均体重などで代わりにするか、欠損として扱う。

### 2. 増えた理由が成長か、太め残りか

- **年齢**: 2〜3歳の休み明けの増加は成長分のことが多い。古馬の大幅増は太め残りを疑う。
- **休養明けかどうか**: 放牧明けの増加は自然。続けて使っているのに増えていれば、調教で絞れていない可能性。
- **追い切りの内容**: 増えていても追い切りの本数が多く時計も良ければ成長寄り。本数が少なく時計も平凡なら太め残り寄り。

### 3. 減った理由が絞れたのか、消耗か

- **間隔**: 中1〜2週の詰まった間隔での減少は、疲れ・消耗のことが多い。
- **輸送**: 美浦から京都・阪神のような長距離輸送では、一時的に減ることがある。
- **方向**: 太め残りだった馬がベスト体重に戻る減少なら、仕上がった可能性。

### 4. 調教師ごとの反応（「人」に注目する方針とつながる）

- 休み明けをわざと太めで使い、次走を本番にする厩舎がある。
- 大幅増でもよく走る厩舎、減ったときに崩れやすい厩舎のように、体重変化への反応は厩舎ごとに違う。
- 「この厩舎で+10kg以上のときの成績」のような厩舎ごとの過去の反応を特徴にする。件数が少ないので、全体平均に寄せる処理（進め方の3番）を必ず入れる。

### 特徴の候補

| 特徴 | 内容 |
|---|---|
| ベスト体重との差 | 今回の体重 − ベスト体重 |
| 前走との差 | いわゆる馬体重の増減 |
| ベスト体重に近づいたか | 前走よりベスト体重との差が縮んだか（はい／いいえ、または差の変化量） |
| 休養期間 | 前走からの週数 |
| 年齢 | 2〜3歳の成長を見分けるため |
| 輸送の有無 | 所属（美浦・栗東）と開催場から判定 |
| 追い切りの本数と時計 | データがあれば |
| 厩舎ごとの体重変化への反応 | 上の4番 |

### 注意点

- パドックでの見た目（腹回りの張り、毛艶、気配）や厩舎のコメントはデータ化しにくい。ただ、オッズにはある程度反映されている。
- この組み合わせが最も効くと確かめたわけではない。PCで、人気だけの予測に上乗せできるかを検証すること。

## ついでにやること: ダブルクリックで起動できる .bat ファイル

開発中は .exe にせず、起動用の .bat ファイルを作って楽に起動できるようにする。

- **.exe にしない理由**: コードを直すたびに作り直しが必要で、開発中は手間が増えるだけ。.exe は完成して他の人に渡すときに検討する。
- **やること**: アプリの起動コマンド（仮想環境の有効化を含む）を書いた .bat を作り、デスクトップにショートカットを置く。
- **確認すること**: 仮想環境（venv や conda）の場所、起動コマンド（`python main.py`、`streamlit run app.py` など）、エラーが出たときに画面がすぐ閉じないようにするか（最後に `pause` を入れる）。

## 1週末分の試し集計で見えたこと

件数が少ないので、傾向の当たりをつける程度に見ること。

- **エージェントごとに回ってくる馬の質が違う**: 平均人気は、井上政行（川田）2.1、豊沢信夫（ルメール、武豊）4.1に対し、小野智美 10.7、高尾幸司 11.2。
- **若手騎手は人気薄が多い**: 若手は平均8.9番人気で10番人気以下が45%。それ以外は平均7.2番人気で32%。
- **同エージェントの同時出走はよくある**: 72レース中69レースで発生。勝率は単独8.1%、同時6.0%。複勝率と平均人気はほぼ同じ。
- **社台系クラブの馬は特定のエージェントに集まる**: サンデー、キャロット、シルクの馬は、中村剛士、目黒和外、豊沢信夫の騎手に多い。
- **厩舎ごとの使い分けの例**: 矢作厩舎は1〜6番人気の6頭中5頭が弟子の坂井・古川奈穂。斎藤誠厩舎は2・3番人気が戸崎、4番人気以下は主に横山琉人。

詳しい数字は次のファイルにある。

- `agent_results_2026-11-07_08.md`: エージェント別成績
- `same_agent_races_2026-11-07_08.md`: 同時出走と単独の比較
- `agent_pairs_2026-11-07_08.md`: エージェント×馬主、エージェント×調教師

## 注意点

- 人気は「騎手が誰か」でも動く（ルメールが乗るから人気になる）。人気を仕上がりの目安にするときは、この点を割り引く。
- 誰が騎手を決めたか（調教師か、馬主か、牧場か）は外からは見えない。データに出るのは結果としての組み合わせだけ。
- このメモは、競馬アプリのモデルの中身を見ずに書いた一般的な方針。PC側で実際の特徴や評価方法に合わせて調整すること。

## PCの Claude Code への頼み方（例）

**1回目（レビュー）**

```
jra_agents/HANDOVER.md を読んで、「最初にやること」に沿って、
この競馬アプリの予想モデルと買い目のコードを全部読んでください。
まだコードは直さずに、問題点と改善案を重要な順に一覧で出してください。
あわせて、修正前の回収率・的中率などを確認できる方法も教えてください。
```

**2回目以降（修正）**

```
一覧の〇番を直してください。直す前と後で、同じ条件の回収率・的中率を比べて報告してください。
```

**起動用の .bat（いつでも）**

```
jra_agents/HANDOVER.md の「.bat ファイル」の章を読んで、
このアプリをダブルクリックで起動できる .bat ファイルを作ってください。
```

**レビューが終わったら（新しい検討）**

```
jra_agents/HANDOVER.md の「進め方」と「馬体重」の案のうち、
今のモデルに効きそうなものを選んで、優先順位をつけてください。
```
